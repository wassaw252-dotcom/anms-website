# ANM’s implementation plan

Brand: Advancing New Milestones / Business Systems Engineering. Black and charcoal, restrained metallic gold, precision typography and a living Canvas network sphere. The supplied reference images inform visual direction; their obsolete copy is not used.

Information architecture: / public narrative with Solutions, Capabilities, How It Works, demonstration Work and About anchors; /discovery persistent adaptive discovery; /privacy disclosure; /dashboard protected pipeline and /dashboard/requests/:id internal review.

UX: TRY US initiates an accelerated core transition; discovery asks one question at a time. Visitor reviews a factual summary, supplies contact and consent, then explicitly submits for engineering review. Only a committed transaction produces the receipt and reference. Optional consultation records interest then opens WhatsApp for manual arrangements. Direct contact is independent.

Motion: intro under 2.5 seconds, Canvas latitude/longitude core and orbital paths, cursor depth, CTA convergence, scroll-linked diagram progress. Mobile uses fewer nodes; hidden/offscreen animation stops; reduced-motion renders a still composition.

Technical: Next.js App Router, React/TypeScript, Tailwind, Framer Motion. Server-only model adapters and modular prompts. A random HttpOnly session capability is hashed with AUTH_SECRET in storage. Supabase REST and Auth are only used server-side. All business tables use RLS with public access revoked; admin routes verify Supabase identity and an active admin_users membership on every request.

Data: conversations and messages; submissions with unique conversation and reference; assessments, opportunity_reports, engineering_briefs, internal_notes, status_history, notifications, admin_users; distributed rate limits and session leases. Transactional RPCs handle turns and final submission. Internal report generation is isolated from the public conversation model.

Build order: foundation → public narrative/motion → discovery and APIs → schema/report pipeline → protected dashboard → WhatsApp → security/build/browser verification → GitHub/Vercel.

Activation dependencies: Supabase project and server key; model provider/key/model; site origin; WhatsApp number; admin Auth user and membership. No fake integrations or hardcoded fallback leads.
